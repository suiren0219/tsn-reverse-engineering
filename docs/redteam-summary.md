# SpoofDetector · 红蓝对抗小结

本轮工作：把 `SpoofDetector` 从"能跑"推到"能量化"，并补齐了红队侧。

**新增三件事**：

1. **红队评测台**（`redteam/`）—— 按真实工具源码公式生成合成攻击样本，离线跑出命中率/误报率矩阵
2. **APK 内自检模式** —— 合成样本灌进真实检测管线，手机上直接看"如果 AnyDoor 跑在这台设备上会报什么"
3. **目标 App 防御侧评估**（`docs/assessment-tsn.md`）—— 检测覆盖矩阵与加固建议

## 二、本轮发现并修掉的三个检测缺陷

### 1. `t2_jitter_ac` 判据方向反了

原实现算「位置增量」的滞后 1 自相关，判 `|ac| < 0.15` 为可疑。

推导：位置噪声 `x_t = φ·x_{t-1} + ε`，增量 `s_t = ε_t + (φ-1)·x_{t-1}`

| 模型 | φ | 增量自相关 |
|---|---|---|
| AnyDoor 逐点独立抖动 | 0 | **≈ -0.5**（MA(1)） |
| 真实接收机环路 | →1 | ≈ 0（趋近白噪声） |

所以**自相关越负越像伪造**，原判据恰好把真机判成可疑。

实测（20 种子）：原判据下对照组误报 20/20，AnyDoor 漏报 20/20。

**修复**：改为直接估计 AR 系数 `φ = 1 - Var(step) / (2·Var(pos))`，判 `φ < 0.3` 可疑。

修复后两组分离干净：

```
真实设备 φ ∈ [0.53, 0.997]
AnyDoor  φ ∈ [-0.14, 0.22]
```

### 2. `t2_sat_staircase` 用采样点数当阈值会误报

原判据 `maxRun >= 5` 报弱信号。但真实设备在 1Hz 采样下卫星数恒定 5~10 个点是常态（同一批星持续被跟踪），对照样本稳定触发 0.3。

AnyDoor 的真正签名是**每 20 秒**才变一次（源码用 `time/20000` 做 hash 输入）。

**修复**：改用时长阈值，≥15s 判 0.6、≥10s 判 0.3。修复后对照组 0.30→0.00，AnyDoor 反而 0.30→0.60。

### 3. `t2_step_cv` 对 FuckRun 无效

FuckRun 用正弦波 + ±15ms 抖动，实测 CV=0.050，正好落在真人区间 `0.02~0.08` 内。

**修复**：新增 `t2_step_period`，判别量取「自相关谷值是否穿零」：

```
真人：    +0.53 +0.54 +0.47 +0.46 +0.38 ... +0.22   （单调衰减，全程为正）
FuckRun:  +0.63 +0.32 -0.06 -0.44 -0.69 -0.73 +0.72 （振荡，穿零）
```

五个种子全部命中，对照组零误报。

### 两个已知无效项（非缺陷）

- **`t2_gnss_alive` 对所有 Xposed 类攻击无效**：这些模块改 `Location` 对象，不碰 HAL，接收机状态是真的。它的价值在**组合证据**——若它 CLEAR 而 `t2_static_alt_acc` DETECTED，说明"接收机是真的，定位数据是假的"，比单条更有说服力。
- **`tishineng-sdk` 端侧零可见**：纯 HTTP 方案不进设备定位栈，八项全部 skip。端侧原理上无解，只能靠服务端。

## 四、APK 内自检模式

设置页 → 「红队自检（合成样本）」→ 运行自检。

合成 `Location` 灌进**同一条检测代码路径**（`recomputeTier2`），不是另写一套逻辑。结果带 `[自检:xxx]` 前缀，可一键清除。

**不联网、不读账号、不碰人脸、不注入进程、不需要 root。**

实现时踩到一个坑：`Location.setAltitude()` 不置私有字段 `mHasAltitude`，而检测侧用 `hasAltitude()` 过滤。不补标志的话合成样本会被当成"无海拔"，该项误报"样本不足"而非给出结论。已用反射补上。

## 五、目标 App 评估（要点）

完整报告见 `docs/assessment-tsn.md`。三个最具体的发现：

1. **`getInstalledPackages` 存在确定性假阴性** —— Android 11+ 未声明 `<queries>` 会静默返回空列表，root 管理器检测得到"未安装"。小改动可修。
2. **`ProcessBuilder` 完全没覆盖** —— 壳只处理 `Runtime.exec`，而 `new ProcessBuilder("su").start()` 是等价路径。
3. **`libproperty_get.so` 直接调 `__system_property_get`** —— 精准设计，Xposed hook Java 的 `SystemProperties.get()` 对它完全无效。FuckTSN 那类模块失效在这一环。

## 七、边界说明

**本仓库不含、也不接受**：

- 任何可装载运行的攻击模块（注入进程、伪造系统定位、绕过检测）
- 反编译产物与第三方版权代码
- 原始 APK、抓包文件、账号凭证

红队侧只提供**合成样本生成器**：按公开可验证的公式生成 `Location` 对象，喂给检测函数，用于量化检测器的命中率与误报率。这与"让伪造定位通过检测"是两件事——前者测检测逻辑，后者是攻击工具。
